# Evidence completeness regression controls

## Source and limits

[AgentTriage v1](https://arxiv.org/abs/2610.30738v1), submitted
2026-10-22, describes deterministic diagnosis from normalized runtime events,
versioned overlays and a pre-run policy oracle, with abstention when required
evidence is missing. The authors report 159 applicable executions across five
runtimes and 120 adjudicated cases: grounded joint diagnosis 0.858,
required-evidence coverage 0.966 and unsupported-claim rate 0.036. These are
author-reported results, not reproduced AIFT results or a complete federation
architecture.

The [public implementation](https://github.com/AsnGs/agenttriage-open-source)
was inspected at `7f3ab28f08677b5ba9e54e41e16212aaa6e677a3`.
Its README identifies Apache-2.0 for the host project, separate upstream
licenses for bundled targets, Python 3.10+, a `jsonschema` host dependency and
Docker for target runs. It explicitly excludes timing, annotation and
evaluator-only code from the release; the full paper evaluation therefore
cannot be assumed reproducible from this release alone. The paper uses the
arXiv nonexclusive distribution license, independently of the code license.
No upstream code was executed, installed or vendored. Telemetry, local-model
support and Termux compatibility have not been audited; adoption is not
recommended on this evidence.

## Small AIFT step

AIFT already validates evidence before preparing its offline Opik payload.
Extend that implementation's tests instead of introducing another tracing
framework: independently omit every required top-level field, each check
field and each assessment status. Require both the Python API and CLI to
reject all 17 incomplete records; the CLI must exit 2, emit no success output,
create no payload and preserve input bytes. Four known-answer cases also
verify that input check order cannot change the exported result.

These controls test evidence completeness and deterministic normalization.
They do not authenticate evidence, establish security assurance, reproduce
AgentTriage's scores or measure an agent reliability improvement. Runtime
behavior, evidence schema and export interfaces are unchanged. PR #6's
separate HEAD-provenance change remains subject to its existing review.

The awesome-ai-agents catalog remains at
`a32e86f60db8dd9556218403532264e0794822c4` (2026-10-04), unchanged
from the previous scan; no new catalog entry is treated as adoption evidence.

Reproduce with `python3 -B -m unittest discover -s tests -p
'test_opik_verification_export.py' -v`, then `bash qa-local.sh` and
`git diff --check` from the repository root.
